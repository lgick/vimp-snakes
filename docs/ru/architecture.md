# Архитектура (игра-плагин)

`vimp-snakes` — **динамический плагин** для [движка VIMP](https://github.com/lgick/vimp-engine)
(публикуется как `vimp-engine` / `vimp-engine-core`): арена змеек «все против
всех», целиком работающая на P2P-инфраструктуре движка (авторитетный
браузерный хост, WebRTC-клиенты, Node.js-мастер для лобби/сигналинга). В этом
репозитории — только игра; транспорт, комнаты, чат, таблица статистики,
эстафета Worker'ов и MVC/рендер-каркас клиента живут в движке, см. его
[architecture.md](https://github.com/lgick/vimp-engine/blob/main/docs/ru/architecture.md).

## Структура репозитория

```
index.html / vite.config.js — Vite-корень плагина (dev-харнесс + две сборки)
dev/main.js  — standalone dev-харнесс (`npm run dev`), не публикуется
src/
  host/      — HostPlugin: роутер событий ядра, StatBridge (подсчёт очков),
               ArenaScaler (карта, растущая с толпой), ScriptedManager (боты),
               чат-команды, системные сообщения группы g
  client/    — ClientPlugin: parts/ (сущности PixiJS), bakers/ (текстура
               кристалла), gameOver.js (экран результата), CSS игры
  config/    — половины конфигурации (game.js, client.js, auth.js, sounds.js,
               snapshot.js)
  data/      — статические данные: maps/arena.js, models.js, palette.js,
               theme.js, weapons.js (пустой по контракту)
  host/nodeCore.js — одна ветка на обе половины плагина: браузерный wasm-ассет
               против Node-склейки (headless-прогоны)
core/        — vimp-snakes-core (Rust → WASM, pkg-web/pkg-node): движение,
               столкновения, кристаллы, боты, предсказание (см. core.md)
assets/      — исходники: audio-raw/ (сырые звуки) и sounds/ (готовые
               заглушки); картинок нет — каждая текстура печётся
scenarios/   — headless-сценарии для движкового `npm run sim`
scripts/     — обработка звука, копирование картинок, экспорт карт, манифест
tests/       — host-модули, клиентские части, контракты конфигов, JS↔WASM
```

`src/config/` и `src/data/` читают host-Worker движка, клиентский бандл и (для
карт) мастер — всё через контракт плагина (`HostPlugin.gameConfig`,
`ClientPlugin`, `GameManifest`), никогда прямым импортом.

## Как плагин подключается к движку

- **Хост**: `host.worker.js` движка динамически импортирует `entries.host`
  этого пакета (`src/host/index.js`, дефолтный экспорт `HostPlugin`) и зовёт
  `createCore()`, который грузит WASM-ядро этого репозитория. `ScriptedManager`
  реализует контракт scripted-модуля движка
  (`createMap`/`getCountsPerTeam`/`createScripted`/`removeScripted`/
  `removeOneForHuman`).
- **Клиент**: клиент движка динамически импортирует `entries.client`
  (`src/client/index.js`, дефолтный экспорт `ClientPlugin`) после выбора
  комнаты и зовёт `createClientCore()` — который ОБЯЗАН вернуть
  `{ core, memory }`: из этой памяти WASM движок каждый рендер-тик читает
  hot-буфер.
- **Обе точки входа принимают `wasmUrl` в двух видах**: хешированный
  `.wasm`-ассет в браузере и `file:`-URL Node-склейки (`entries.wasmNode`) под
  headless-раннером движка. Ветка живёт в `src/host/nodeCore.js` и намеренно
  общая для обеих половин — headless-прогон на другом ядре ничего бы не
  доказывал.
- **Мастер** никогда не исполняет код плагина — он только отдаёт
  `dist/manifest.json` этого пакета и экспортированный JSON карты под
  `/games/snakes/*`.

Полный контракт — движковый
[plugin-api.md](https://github.com/lgick/vimp-engine/blob/main/docs/ru/plugin-api.md).

## Граница ядра

Только симуляция: движение, рост, столкновения, поле кристаллов, боты и
упаковка бинарных кадров — в `core/` (Rust/WASM). Мета (чат, таблица
статистики, реестр участников, комнаты, авторизация) — JS движка,
параметризованный конфигом этой игры, с одним намеренным исключением: подсчёт
очков игра ведёт сама (см. ниже).

**Физики нет.** Змейка — это ломаная; граница арены, чужие тела и кристаллы —
проверки расстояний. Rapier-мир движка создаётся и шагает, но остаётся пустым.
Именно это делает клиентское предсказание точным: предиктор гоняет тот же
`core/src/motion.rs`, что и хост, и между ними нет солвера, которому было бы с
чем не согласиться.

## Клиентская сторона

Из трёх механизмов сглаживания сети используются два:

- **Предсказание** (`core/src/client/predictor.rs`): локальная змейка
  считается репликой авторитетной модели движения (формулы общие через
  `core/src/motion.rs`); хост подтверждает ввод (`lastInputSeq`),
  реконсиляция переигрывает неподтверждённый ввод, расхождение затухает
  плавно. Spawn-grace отсчитывают обе половины синхронно, поэтому реплика
  трогается с места на том же тике, что и хост.
- **Интерполяция** целиком движковая (игрового кода нет).
- **Клиентский спавн действий намеренно отсутствует**: у змейки нет оружия, а
  все её взаимодействия решает хост, поэтому `hooks.onLocalAction` возвращает
  `null`, а `try_action` пуст. Угадывать крушение локально — значит показать
  игроку смерть, с которой хост может не согласиться.

Рендер собран из MVC-компонентов движка и сущностей PixiJS этого плагина
(`src/client/parts/`) на одном канвасе (`vimp`); текстура кристалла печётся на
старте из `src/client/bakers/`.

Игровых сервисов частям не нужно: в `componentDependencies` названы только
движковые (`soundManager`, `localPlayer`). Цвета и вид арены — обычные импорты
(`src/data/palette.js`, `src/data/theme.js`), потому что произвольный ключ
`gameConfig.parts.*` доходит до клиентского конфига, но никогда до части:
часть конструируется как `(data, assets, dependencies)`, а `dependencies`
хранит только движковые сервисы.

## Четыре решения, на которых держится код

1. **Ядро владеет жизнью и смертью; движку об этом не сообщают.**
   `CoreEvent::Death` не эмитится никогда. Раунд заканчивается только через
   отчёт об убийстве, а поштучного респавна внутри раунда нет (единственный
   примитив спавна приватен для `RoundManager._startRound`) — значит, ядро
   обязано владеть крушением, россыпью и респавном целиком. Поэтому движок не
   пишет и `score`/`deaths` — это делает `src/host/StatBridge.js` по `custom`
   событиям, добираясь до них из `onCoreEvent` через модульную ссылку,
   выставленную в `createModules` (контекст этого хука — только
   `{ vimp, panel }`). Два движковых флага в `src/config/game.js` делают это
   официальным: `noSpectators` (одна команда, вошедший сразу в ней) и
   `endlessRound` (движок сам не перезапускает раунд и не чистит таблицу).
2. **Игровые id — СТРОКИ.** Движок раздаёт их как `counter.toString(10)` и
   ключует ими Map участников, а ядро пишет их в `custom` события числами —
   всё, что пересекает этот шов, проходит через `String()`. Ошибка здесь
   заморозила панель и таблицу на нуле (страхует
   `tests/host/statBridge.integration.test.js`).
3. **Арена выводится из сетки карты и растёт с толпой.** Одна формула в
   `core/src/arena.rs`, `src/client/parts/Arena.js` и `src/data/maps/arena.js`:
   `radius = cols * step / 2`. Размер сетки следует за населением: ядро
   сообщает `population`, `src/host/ArenaScaler.js` пересобирает карту
   `buildArena(count)` и подменяет её на лету через `coreAdapter.createMap` +
   `socketManager.sendMap` + `vimp.overrideMapData` — но не движковой сменой
   карты, которая стёрла бы счёт.
4. **Поворот — одна функция, два источника.** Клавиши и точка указателя
   (`MoveInput.aim`, мировая точка из движкового `apply_aim`) сводятся к
   ограниченному шагу `motion::step_angle`, поэтому мышь не поворачивает
   быстрее `turnSpeed` — и цель обязана попадать в историю ввода предиктора
   (`InputSnapshot`), а не только в маску клавиш.

## Ключевые инварианты

- **Один экземпляр PixiJS**: движок и плагин обязаны делить один модуль в
  рантайме. `pixi.js` — peer-зависимость, вынесенная из клиентской сборки
  (`vite.config.js`); страница хоста резолвит её через import map. Вторая
  копия ломает взаимодействие рендер-систем движка с объектами PixiJS плагина.
- **Паритет реплики движения**: авторитетный шаг и клиентская реплика делят
  формулы (`core/src/motion.rs`); паритет закреплён cargo-тестами
  (`client::predictor::parity`) — любая правка движения или коэффициентов в
  `models.js` требует `npm run core:test`.
- **Блок игрока несёт `cos`/`sin`, а не угол**
  (`PLAYER_STATE_LEN = 8`: `[x, y, cos, sin, crystals, length, alive, grace]`).
  Детектор дрейфа сравнивает компоненты численно, и сырой угол на переходе
  через ±PI читается там как расхождение в 6.28 рад. Последний слот — это
  СЕКУНДЫ оставшейся неуязвимости, а не флаг: флаг заморозил бы реплику на
  круг дольше хоста.
- **`SPINE_POINTS = 16`** — ресемпл тела в строке змейки; объявлен в
  `src/config/snapshot.js`, `core/src/motion.rs` и
  `src/client/parts/Snake.js`, сверяет их `tests/config/contract.test.js`.
- Схема ключей снапшота (`src/config/snapshot.js`) — данные этого плагина;
  незарегистрированный ключ ломает упаковку кадра на обеих сторонах, поэтому
  движковый блок `c1` (динамика карты) объявлен, хотя динамических тел в игре
  нет.
- `ENGINE_API_VERSION` всегда импортируется из
  `vimp-engine/config/opcodes.js`, никогда не пишется литералом; движок
  сверяет его при загрузке плагина.
