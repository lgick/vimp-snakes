# Rust Game Core (core/)

`vimp-snakes-core` is this game's simulation, built on top of the engine crate
`vimp-engine-core`. It compiles to WASM twice — a browser/Worker build
(`core/pkg-web/`) and a Node build (`core/pkg-node/`, for tests and the
headless runner) — and exports exactly two classes:

| Class | Runs in | Owns |
| --- | --- | --- |
| `GameCore` | the room host's Web Worker | the authoritative match |
| `ClientCore` | every player's tab | interpolation (engine) + prediction of the local snake (this crate) |

Everything the engine calls on them is generated by two ABI macros —
`export_game_core_abi!` and `export_client_core_abi!` — so `core/src/lib.rs`
hand-writes only the constructors and the two game-specific client methods.
The generic contract is the engine's
([05-wasm-core.md](https://github.com/lgick/vimp-engine/tree/main/docs/ai));
this page documents what *this* game puts inside it.

**There is no physics module and there are no body tags.** A snake is a
polyline, and everything that can kill it is a distance test. The engine's
Rapier `PhysicsWorld` is still created and still stepped — it is simply empty.

## Layout

```
core/src/
  lib.rs        — the two exported classes, config parsing, the ABI macros
  config.rs     — the `game` half of the init JSON: SnakeConfig, WorldConfig,
                  CrystalTier, KeyConfig, panel keys; validation
  motion.rs     — THE shared math: step_angle, speed_of, advance_head,
                  radius_for, length_for, turn_speed_for, BodyPath
  snake.rs      — one snake: keys held, the body it drags, step(), respawn(),
                  the spawn grace, prediction_state()
  game.rs       — the authoritative sim (GameSim): spawn/kill/revive, the
                  fixed step, collisions, bots, snapshot rows, custom events
  arena.rs      — the disc derived from the map grid, and `contains()`
  crystals.rs   — the crystal field: spawn, pickup, death drops, the delta
                  block and its resync
  client/
    mod.rs      — GameClientDef: the hot buffer overlay, the player block
    predictor.rs— the replica of the authoritative motion + reconciliation
```

`motion.rs` is the file both halves share. **Moving logic out of it
desynchronises prediction from the server** — that is what the parity suite
in `client/predictor.rs` exists to catch.

## Build

```bash
npm run core:build        # both targets
npm run core:build:web    # wasm-pack --target web    → core/pkg-web/
npm run core:build:node   # wasm-pack --target nodejs → core/pkg-node/
npm run core:test         # cargo test --workspace
```

`core/pkg-web/` is what the browser loads (and what `npm run dev` imports
directly); `core/pkg-node/` is what `npm test`'s `integration` project and the
engine's headless runner use, and what `npm run build` copies into
`dist/core-node/`.

The crate depends on `vimp-engine-core` from crates.io, pinned in the
workspace `Cargo.toml`. `rapier2d` carries `enhanced-determinism`, and
`indexmap` is used instead of `HashMap` wherever insertion order is a contract
(models, panel fields, snakes).

## ABI: commands, events, frames

### Commands (`GameCore`)

The engine's `GameCoreAdapter` calls the macro-generated surface: `load_map`,
`spawn_actor`, `remove_actor`, `reset_actor`, `reset_all_vitals`,
`spawn_scripted_actor`, `remove_scripted_actor`, `apply_input`, `apply_aim`,
`step`, `take_events`, `last_input_seq`, `is_alive`, `position_of`,
`players_data`, `alive_players`, `pack_body`, `pack_frame`, `frame_ptr` /
`frame_bytes`, `serialize_state` / `deserialize_state`, `debug_json`.

What this game implements behind them (`impl GameSim<SnakesGame> for
SnakesSim`, `core/src/game.rs`):

- **`spawn_actor` / `spawn_scripted_actor`** — creates a `Snake` at a free
  spot. The engine's suggested point is only a suggestion: `find_spawn_from`
  walks the map's own respawn points in bit-reversed order and, failing that,
  throws `RESPAWN_ATTEMPTS` (24) random candidates, keeping
  `RESPAWN_CLEARANCE` (140) from every existing body. A newly spawned snake is
  laid out **whole** (`Snake::lay_out_body`) and armed with the spawn grace.
  Because the body is laid straight backwards from the head, every candidate —
  the engine's point, a map slot, a random throw — is held to
  `SnakesSim::spawn_margin`, which is `edge_margin` **plus the body length**
  and not `edge_margin` alone. The inset is radial, so it holds for any
  heading, including the engine's own when the requested point is honoured; a
  head on the bare `edge_margin` ring used to leave the tail outside the disc,
  where nothing kills it. When the model is unknown the margin falls back to
  the widest any known model needs, never to the bare `edge_margin`.

  **That check is made against the arena of the LAST fixed step**, and it has
  to be re-made: `spawn_actor`, `reset_actor` and `spawn_scripted_actor` are
  called by the engine outside the step, while `self.arena` and
  `self.spawn_slots` are rebuilt only inside it. `RoundManager._startRound`
  swaps the map and places every actor in one synchronous pass, so a round
  restart right after a resize lays everyone out on the previous geometry. The
  answer is `reseat_stranded`, which runs at the top of every step, with the
  new disc and the new slots already in hand and before anything moves: any
  living snake still in its spawn grace whose body is not wholly inside the
  disc is moved to a fresh spot, and the REMAINDER of its grace is handed back
  untouched (`Snake::grace_left`) — a reseat that refreshed the grace would be
  a way to stay unkillable. Because the move happens while the snake is frozen
  and blinking, it is invisible.

  The same mechanism covers the other direction: a snake in grace is skipped
  by section 1 of the step and therefore never tested against the boundary in
  section 2, so an arena that shrinks over its two frozen seconds would leave
  it standing outside the ring until the grace ran out and the edge killed it.
- **`apply_input`** — maps an action name to its bit via `KeyBits` (built from
  `gameConfig.playerKeys`); `type: 1` keys (`respawn`) are armed by `down` and
  consumed by exactly one fixed step.
- **`apply_aim`** — the pointer target as a world point plus flags (held /
  double-tap boost). It becomes `MoveInput.aim` and is cancelled the moment a
  turn key is held.
- **`is_alive` / `position_of` / `alive_players`** — read off the head of the
  polyline.
- **`players_json`** (the JSON behind `players_data`) — every snake, alive or
  dead, in **schema order**. Two contracts meet here: a dead snake is still a
  participant (the engine was never told it died), and this payload is the
  first full frame a joining client gets.
- **`reset_actor`** — the engine's round restart; it respawns the snake in
  place of a per-player respawn this game cannot ask for.

### Events (`take_events()`)

The engine's standard dictionary is used only in part. `PanelSet` and
`PanelActive` go to the HUD; **`Death` is never emitted** (see
[architecture.md](architecture.md#the-four-decisions-the-code-depends-on));
`Shake` is unused. Everything this game needs beyond the panel travels as
`CoreEvent::Custom`, which the engine routes verbatim to
`HostPlugin.onCoreEvent`:

| `data.type` | Payload | Consumed by |
| --- | --- | --- |
| `crystals` | `{ id, total, gained }` | `StatBridge` — the score and `eaten` |
| `burn` | `{ id, burned, total }` — emitted on every step the boost sheds crystals, `burned` counting the spots dropped that step | `StatBridge` — takes them off the score, so boosting is not free |
| `death` | `{ id, crystals, crashes, killer }` (`killer: null` for the edge) | `StatBridge` — the kill bonus, the end of the victim's game, the saved profile |
| `respawn` | `{ id }` | `StatBridge` — a new life is a new game, so the counters start at zero |
| `spawn` | `{ id, color }` — the palette index the core handed out at `spawn_actor` | `ChatColors` — the colour of that player's nickname in chat |
| `population` | `{ count }` | `ArenaScaler` — rebuilds the map; `StatBridge` — publishes newcomers' rows |

Ids are **numbers** here and **strings** in the engine — everything crossing
that seam goes through `String()`.

### Frames

Frame packing is the engine's (v3 layout, `SnapshotPacker`); this game
supplies the blocks, declared in `src/config/snapshot.js` and filled in
`game.rs`:

- **`s1`** (`indexed8`, class `hot`) — one row per snake: 16 spine points
  (32 floats, head first), `angle`, `radius`, `crystals` (u16), `color` (u8),
  `boost` (u8). The last byte carries two bits: bit 0 the boost, bit 1 the
  spawn grace (`boost_byte`).
- **`cr`** (`indexed32`, class `event`) — the crystal field as a **delta**: a
  row when a crystal appears, a `null` row when it is eaten. Re-sent in full
  whenever an actor spawns, because a joining client has missed every row so
  far.
- **`c1`** (`indexedNoNull8`, class `hot`) — the engine's map-dynamics block.
  This game has no dynamic bodies and the block stays empty, but it must be
  declared: the packer refuses a key it does not know.

### State queries

`prediction_state` returns the player block —
`[x, y, cos, sin, crystals, length, alive, grace]`, `PLAYER_STATE_LEN = 8`.
Two details are load-bearing: the heading travels as **cos/sin** (the drift
detector compares components, and a raw angle crossing ±PI reads as a 6.28 rad
divergence), and the last slot is the **seconds of grace left**, not a flag —
a flag would keep the replica frozen a round trip past the moment the host
resumed.

## The motion model (`motion.rs`)

There is no acceleration and no inertia. One step is:

```text
angle  = step_angle(head, angle, input, turn_speed_for(crystals), dt)
speed  = speed_of(input, can_boost, model)          // base or base * boostFactor
head   = advance_head(x, y, angle, speed, dt)
path.advance(head, model.point_spacing)             // lay a breadcrumb
path.trim(length_for(crystals, model))              // cut the tail back
```

- **`step_angle` is the one turn function, and it has two sources.** Keys ask
  for "current angle ± one step"; the pointer asks for "the angle onto that
  point". Both are clamped to `max_turn * dt`, so a mouse can never out-turn
  `turnSpeed`. A pointer target closer than `AIM_DEAD_ZONE` (4 units) is
  treated as reached, so the snake does not spin around the finger.
- **`turn_speed_for`** is the mirror of `radius_for`: the same `sqrt(crystals)`
  curve, falling instead of rising, clamped at `turnSpeedMin`.
- **`BodyPath`** is a `VecDeque` of breadcrumbs, head first. Growth means
  trimming *less* off the tail, so the body is always exactly as long as the
  crystal count says — there is no per-segment bookkeeping anywhere.
  `resample()` produces the fixed 16-point spine the wire carries;
  `reset_with_body()` lays a whole body out straight behind a head, which is
  what makes a snake spawn whole.

## Collisions (`game.rs`, the fixed step)

The step is four passes, in this order, and the order is the rule:

1. **Move** every living snake (or burn down its grace — a snake in grace does
   not move, does not kill, cannot be killed and does not eat).
2. **Decide what kills whom**, collecting into a list rather than applying as
   it goes: two snakes that run into each other on the same step must both
   die, and resolving in place would let whichever is iterated first take the
   other out and survive.
   - the head against the arena: `arena.contains(head, radius)` — the boundary
     catches the snake, not its centreline;
   - the head against every other body: a broad-phase AABB, then
     `BodyPath::touches_ahead(head, radius_a + radius_b, facing)`. **Ahead** is
     the fault rule: the contact has to lie in the half-plane the head faces,
     so a snake rammed from the side or from behind survives and the one that
     drove into it does not. Its own body is skipped entirely — the head
     passes over its own tail.
3. **Pick up crystals** for whoever survived this step.
4. **Apply the kills**: `kill()` empties the snake, scatters `drop_ratio` of
   what it carried over `DEATH_DROP_SPOTS` (24) positions along the body it
   was dragging (biggest tier the remaining budget can pay for, so a big snake
   leaves a pile worth crossing the arena for), pushes the two panel cells and
   emits the `death` custom event. Respawn is a separate, player-requested
   step: `revive()` runs when the `respawn` bit is consumed.

## The crystal field (`crystals.rs`)

One `IndexMap<u32, Crystal>` plus two delta accumulators drained per packed
frame. Natural spawns run on a timer (`spawn_interval`) while the field is
below `max_crystals`, at a random point inside the disc minus `edge_margin`,
with the tier rolled from `tier_weights`. Pickup is a distance test against
the head. `request_resync()` re-sends the whole field; `game.rs` calls it on
`spawn_actor` and `reset_actor` and **not** on `revive`. A joining client has
seen no delta at all and needs the field; a respawning one has had every delta
since it joined, and one life is one game here, so resyncing on each respawn
would put the whole field on the reliable channel several times a second for
nothing.

**A shrinking arena takes its crystals with it.** The disc is rebuilt under
the running match, and when it shrinks everything left in the old ring is
outside the new boundary. Those crystals are unreachable rather than merely
awkward: a head is stopped at `radius - snake_radius` and reaches
`snake_radius + tier.radius`, so the snake radius cancels and nothing, thin
or fat, ever gets within `radius + tier.radius` of the centre. They also keep
counting against `max_crystals`, so the field stops refilling and the arena
starves on food nobody can eat — a 2560 → 1280 shrink stranded 44 of 60.
`retain_inside()` drops them as ordinary `null` rows on the step
`on_fixed_step` sees the radius or the centre change.

The sweep runs at the END of that step, not at the top of it. A shrink is
exactly the step on which the snakes left in the old ring hit the boundary
and die, and `kill` drops their pile along the BODY — hundreds of units of
it, all outside the new disc. Sweeping first would sweep before the mess is
made, and nothing would come for it until the next resize.

**No crystal is ever outside the disc**, and the shrink is not the only way
one could get there. Both callers of `drop_at` — the boost tax behind the
tail and the pile of a dead snake — drop along a body, and a body reaches past
the boundary every time a snake dies on it, which is how most of them die. So
`drop_at` itself clamps the point onto the disc (`Arena::clamp_inside`, with
`edge_margin`): the pile of a snake killed by the edge is tucked slightly
inwards, which is where it can be collected. Behind that, `retain_inside()`
also runs once a second (`SWEEP_EVERY_STEPS`) and not only on a resize — the
rule is an invariant of the field, and a rule that only runs on one event
holds only until the next feature drops a crystal somewhere else.

## Bots

`drive_bot` (`game.rs`) is deliberately small: a bot steers for the nearest
crystal and swerves when the thing `BOT_LOOKAHEAD` (220 units) ahead of it
would kill it — the arena edge or another body. It writes the same
`MoveInput` a player's keys produce, so there is exactly one movement path in
the game. Bots are engine participants (they appear in the stat table and hold
a slot); the JS half of the contract is `src/host/ScriptedManager.js`.

## ClientCore — the core's client mode

`client/mod.rs` implements `GameClientDef`:

- **`render_overlay`** — after the engine has interpolated the remote snakes,
  the local one's row is overwritten with the predicted spine, so the player's
  own snake never lags behind their input. `crystals` and `color` are read
  back from the authoritative row (`ROW_CRYSTALS`, `ROW_COLOR`) rather than
  guessed.
- **`predictor.rs`** — the replica. `apply_input`/`apply_aim` push into an
  input history; `update` integrates fixed steps of `timeStepMs`;
  `on_server_state` rewinds to the authoritative player block and replays
  every input newer than it, with the visual error decaying over
  ~100 ms instead of snapping — unless it exceeds `ERROR_SNAP_DISTANCE`
  (100 units), which is a teleport (a respawn) rather than drift and is
  applied at once. A respawn is
  detected as `dead → alive` and resets the path — laid out whole, exactly as
  the host does it.
- The grace is counted down here too, step for step, so both halves start
  moving on the same tick.
- `set_model` (called from `hooks.onAuth`) and `sync_panel` (from
  `hooks.onPanel`) are the only hand-written client methods.

## Determinism

The headless runner's `--determinism` flag replays a scenario and compares
frame hashes; all five scenarios are expected to pass. What keeps them
passing: the engine `Rng` is the only source of randomness (crystal spawns,
tier rolls, respawn throws), `IndexMap` keeps iteration order stable,
`round2()` quantises what goes on the wire, and no wall clock is read inside
the step.

## Tests

`cargo test --workspace` runs ~96 tests, all inside the crate:

| Module | What it pins |
| --- | --- |
| `motion.rs` | the turn clamp, both input sources, growth curves, `BodyPath` (advance/trim/resample/touches/`touches_ahead`/`reset_with_body`) |
| `snake.rs` | key semantics (held vs one-shot), the pointer, the boost drain and its floor, respawn, the grace, the prediction block |
| `game.rs` | the grace (frozen, harmless, unkillable), the fault rule, spawning whole, respawn placement (spread, map points first, no self-collision), the boost byte, the `burn` event reporting every crystal the boost sheds, row width vs the schema |
| `crystals.rs` | spawn cadence and cap, pickup, death drops, the delta and the resync, the crystals a shrinking arena leaves behind |
| `arena.rs` | the disc derived from a grid, `contains` with a radius |
| `client/predictor.rs` | **the parity suite** — the replica and the authoritative step must produce the same positions from the same inputs, including through the grace |

`tests/core/nodeCore.test.js` (Vitest, `integration` project) drives the real
Node build from JS: config → `GameCore` → `step` → `pack_frame` →
`ClientCore`, which is the seam a Rust test cannot cover.
