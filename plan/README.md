# План: 9 доработок Vimp Snakes (+ движок)

Индекс. Девять пунктов пользователя разложены на восемь этапов — порядок не
по номеру пункта, а по зависимостям (счёт должен устояться до того, как
таблица stat начнёт его показывать; ранг нужен до колонки «Rank»).

## Контекст

Игра уже играбельна, но плейтест вскрыл девять проблем: змеи появляются
внезапно и в куче, длинная змея вертится как короткая, очки разгоняются,
`/rank` не растёт, в stat лишние колонки и лишние строки-наблюдатели, а
канвас прижат в угол чёрной полосой. Часть из этого чинится в игре, часть —
только в движке.

## Решения пользователя (зафиксированы, не переспрашивать)

1. **Очки за убийство** — фиксированный бонус (`score = eaten + kills *
   KILL_BONUS`), никакого переноса счёта жертвы целиком.
2. **Наблюдатели убираются как концепция движка** для одно-командных игр —
   не «пустой резерв в конфиге», а opt-in флаг `noSpectators` + прямой вход
   в играющую команду (`RoundManager.admitPlayer`), не ломающий другие игры.
3. **Правило «активных людей < 2 → `stat.reset()` + новый раунд»** глушится
   ОТДЕЛЬНЫМ флагом `endlessRound`, не смешанным с `noSpectators`.
4. **Чёрная полоса — не потолок канваса.** Движок обязан центрировать
   леттербокс; `aspectRatio: '16:10'` остаётся.
5. **Числа новых механик:** `spawnGraceSeconds = 2.0`, `KILL_BONUS = 15`,
   `turnSpeed(c) = max(1.4, 3.4 − 0.18·sqrt(c))`.

## Что проверено в коде (правки к предварительному плану)

- **Этап 3, диагноз был неверен.** `ScriptedManager.createScripted` **уже**
  клэмпит по числу точек спавна (`_hasRoom`, `ScriptedManager.js:91`), а
  `respawns.players` — 64 точки при `roomDefaults.maxPlayers: 32`; выхода за
  границу массива нет. Настоящих причин две, обе новые: раздача точек
  подсолнуха по возрастанию радиуса и сброс размера арены на `/bot`. См.
  [stage_3.md](stage_3.md).
- **Этап 8, опасение снято.** `CanvasManagerModel.resize` считает
  `currentScale = width / designWidth * baseScale`, поэтому видимая ширина
  мира — всегда 1920 единиц независимо от монитора. Преимущества по обзору
  нет уже сейчас; чинится ровно центрирование. См. [stage_8.md](stage_8.md).
- **Этап 5 и 7 подтверждены.** `playerDataSync.addRank` вызывается только из
  `RoundManager.reportKill`; `HostGame.createUser` безусловно кладёт человека
  в `spectatorTeam` и пишет строку в stat — крючка для плагина нет.

## Что затрагивает движок

Этапы 5, 7, 8 правят `vimp` в `/Users/dmitry/Sites/my/vimp`. Как и в
предыдущем плане (`plan/done/snakes-fixes.md`), каждая такая правка обязана
получить запись в `packages/engine/CHANGELOG.md` с подзаголовком уровня
релиза (`### Added` / `### Changed` / `### Fixed` / `### ⚠️ Breaking`), см.
`docs/en/publishing.md`. Версии не редактировать и не публиковать самому.
Крейт `vimp-engine-core` ни один этап не трогает, поэтому сверка с
`vimp-tanks` не требуется — но полный сьют движка обязателен, код общий.

## Общая проверка (после каждого этапа)

В `~/Sites/my/vimp-snakes`:

```bash
npm run core:build      # если менялся core/
npm run core:test       # если менялся core/
npm run check:contract
npx eslint . && npm test
npm run build
```

Из чекаута движка (`~/Sites/my/vimp`), с прилинкованным пакетом:

```bash
npm run sim -- --game ~/Sites/my/vimp-snakes \
  --scenario ~/Sites/my/vimp-snakes/scenarios/<name>.json --determinism
```

Для правок самого движка — его `npx eslint . && npm test`.
