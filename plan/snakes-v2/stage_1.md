# Этап 1: lobby, клиппинг звука, чужие звуки

Пункты пользователя 8, 3, 4. Правки только в `vimp-snakes`, плюс
регистрация игры в конфиге мастера (не в опубликованном коде — см. 1.1).

## 1.1. Кнопка `#lobby-host` неактивна — это конфигурация, не баг

**Диагноз подтверждён чтением кода, правок движка не требует.**

Цепочка:

- `packages/engine/src/client/main.js:131` — активной игрой становится
  `gamesManifest.find(m => m.id === boot.gameId)`, а если `boot.gameId` не
  задан, то **`gamesManifest[0]`**, то есть первая игра каталога мастера.
  `boot.gameId` приходит только в dedicated-режиме (`src/client/boot.js:34`),
  в лобби его нет никогда.
- `packages/engine/src/client/lib/hostGate.js:7-16` — кнопка гасится для
  любой игры, кроме активной, потому что хост всегда поднимает
  `activeGameManifest` (динамическая загрузка ClientPlugin по выбору в
  выпадающем списке отложена, это известная граница).

Сейчас `packages/engine/src/config/master.js:29` содержит только
`{ id: 'tanks', package: '@vimp-games/tanks' }` — snakes в каталоге нет
вообще, поэтому её нельзя ни выбрать, ни захостить.

**Шаги:**

1. Проверить, что пакет прилинкован в оба конца (`npm link` в snakes и
   `npm link @vimp-games/tanks @vimp-games/vimp-snakes` в движке — линковать
   обе игры **одной командой**, иначе вторая перетирает символьную ссылку
   первой).
2. Запускать мастер с переменной окружения `GAMES_MATRIX` (JSON), поставив
   snakes **первой** в списке — так `gamesManifest[0]` окажется snakes и
   кнопка станет активна. Это штатный путь: `master.js` прямо документирует,
   что в проде список переопределяется этой переменной, и он **не трогает
   опубликованный код** — в отличие от правки массива `games` в самом
   `master.js`, который входит в `files` пакета `vimp-engine`.
3. Зафиксировать готовую команду запуска в `README.md` пакета snakes
   (раздел «Run it»), чтобы её не приходилось выводить заново.
4. Если после этого кнопка всё ещё неактивна — только тогда заводить
   доработку движка (динамическая загрузка ClientPlugin по выбору), отдельной
   задачей, не расширяя этот этап.

**Проверка:** мастер поднят, в лобби выбрана snakes, `#lobby-host` активна,
комната создаётся, второй вкладкой в неё можно войти.

## 1.2. Не озвучивать чужие подборы и чужие столкновения (пункт 4)

Сейчас `src/client/parts/Snake.js` играет `pickup`, когда растёт **его
собственный** счётчик кристаллов, и `death` из `destroy()` — и то и другое
для каждой змейки на сцене, позиционно.

**Шаги:**

1. Выяснить, как part узнаёт, что он — локальный игрок. Кандидаты, проверить
   по коду движка перед правкой: идентификатор в `data`, флаг у части,
   отдельный канал. Если готового признака нет — самый дешёвый честный путь
   передать его из `ClientPlugin.hooks` в модульную переменную клиента
   (тем же приёмом, каким `createModules.js` держит `StatBridge` для
   `onCoreEvent`).
2. Обернуть оба вызова `_play(...)` условием «это локальная змейка».
   Визуальная часть событий (вспышка подбора, исчезновение) остаётся для
   всех — глушится только звук.
3. Тест в `tests/client/parts.test.js`: чужая змейка при росте счётчика и
   при `destroy()` не дёргает `soundManager`, локальная — дёргает.

## 1.3. Клиппинг звука (пункт 3)

Гипотеза: клиппинг — это **сложение** множества одновременных `pickup` с
одинаковыми приоритетом и громкостью (`src/config/sounds.js:19` —
`priority: 80, volume: 0.35`), а не дефект пула голосов движка.

Важно: пункт 1.2 сам по себе снимает бо́льшую часть нагрузки — после него
`pickup` звучит только для одного игрока вместо всех сразу. Поэтому:

**Шаги:**

1. Сначала выполнить 1.2 и **переслушать**. Если клиппинг ушёл — записать
   это в план как разрешённое и не трогать конфиг.
2. Если остался — понизить `volume` у `pickup` и развести приоритеты
   `pickup`/`death`, чтобы смерть не тонула в подборах.
3. Если и это не помогает — добавить в `Snake.js` дроссель: не чаще одного
   `pickup` на змейку в N мс (значение подобрать на слух, начать с 60 мс).
4. Только если клиппинг воспроизводится на уровне пула голосов при одном
   источнике — заводить отдельную задачу на `SoundManager` движка. **Не
   включать её в этот этап превентивно.**

**Проверка:** ручная, на слух, в браузере — змейка проезжает плотную россыпь
кристаллов, звук не хрипит; смерть слышна поверх подборов.
