# План: доработки Vimp Snakes (v2)

Индекс. Восемь пунктов пользователя разложены на четыре этапа так, чтобы
каждый следующий опирался на готовое предыдущего, а правки движка были
собраны в конце и отделены от правок игры.

## Решения пользователя (зафиксированы, не переспрашивать)

1. **Лимит игроков задаёт игра, движок его не ограничивает.** `master.js →
   maxPlayersLimit` перестаёт быть потолком; потолок берётся из манифеста
   игры (`roomDefaults.maxPlayers`).
2. **Убийство даёт весь счёт жертвы целиком** (`score += victimScore`).
   Кристаллы жертвы при этом всё равно рассыпаются — награда двойная,
   это осознанно.
3. **Указатель — новый примитив движка**, а не эмуляция клавиш на стороне
   игры.

Порядок не произволен:

- **1 перед всем** — пока кнопка `#lobby-host` неактивна, ни один пункт
  нельзя проверить в браузере вдвоём; звук — изолированные правки, дешёвые
  и не мешающие остальному.
- **2 перед 3** — схема очков (`eaten`/`kills`/`score`) должна устояться до
  того, как в арену придут десятки игроков: менять схему панели на
  нагруженной сцене дороже.
- **3 перед 4** — масштабирование арены меняет `MAP_DATA` в рантайме;
  указатель считает мировые координаты от камеры и карты, и его лучше
  отлаживать на уже стабильной геометрии.
- **4 последним** — единственный пункт, меняющий контракт плагина
  (`docs/ai/04-client-plugin.md`) и, возможно, `ENGINE_API_VERSION`.

## Что затрагивает релиз движка

Этап 1 тоже (не планировалось): каталог игр мастера читает `GAMES_MATRIX` и
в dev, а без неё собирается из `node_modules` (`### Changed` + `### Added`);
признак «свой персонаж» сделан примитивом
движка — сервис `localPlayer` и id экземпляра в конструкторе part'а,
`### Added` в `packages/engine/CHANGELOG.md` (минор). Решение пользователя:
делать один раз в движке, а не повторять в каждой игре. Подробности —
stage_1.md, пункт 1.2. tanks на новый признак в этом этапе не переводится.

Этап 2 движка не коснулся, но вопреки ожиданию пункта 2.1 коснулся крейта
`core/`: панель лишилась поля `length` (его требовал `SnakesConfig::validate`),
а событие `crystals` стало нести приращение `gained` — разница по носимому
`total` неверна и после буста, и после респауна. Подробности — stage_2.md,
раздел «Что сделано и где отклонились от плана». Публикуемый код движка не
менялся, поэтому записи в его `CHANGELOG.md` этап не требует.

Этап 3 выполнен: правка опубликованного кода мастера получила запись
`### Changed` в `packages/engine/CHANGELOG.md` (патч — ни одна ранее валидная
конфигурация не отвергается). Крейт `vimp-engine-core` не менялся, поэтому
`vimp-tanks` за движком идти не обязан; крейт игры (`core/`) менялся, но он
принадлежит только этому пакету.

Этап 4 выполнен по варианту А: `### Added` (минор) в обоих changelog'ах —
и в `packages/engine/CHANGELOG.md`, и в `packages/engine/core/CHANGELOG.md`
(тронут крейт: `apply_aim` с дефолтной реализацией в двух трейтах).
`ENGINE_API_VERSION` не поднимался: ядро без нового метода ведёт себя
ровно как прежде. `vimp-tanks` правок не потребовал — проверено сборкой и
его тестами. На время, пока новый `vimp-engine-core` не опубликован, в
`Cargo.toml` змейки лежит `[patch.crates-io]` на локальный чекаут движка;
перед релизом его надо снять (`docs/en/publishing.md`, «Rust side»).

Этап 4 правит опубликованный код `vimp-engine` (и, вероятно, крейт
`vimp-engine-core`). По правилам движка каждая такая правка обязана в том же
изменении получить запись в соответствующий `CHANGELOG.md` с подзаголовком,
задающим уровень релиза. Версии не редактировать и не публиковать — это
делает разработчик через `npm run release`. Подробности — в
`docs/en/publishing.md` чекаута движка.

Ожидаемые уровни (уточняются при реализации):

- этап 3 — `### Changed` в `packages/engine/CHANGELOG.md` (патч), если снятие
  потолка не отвергает ни одну ранее валидную конфигурацию;
- этап 4 — `### Added` (минор), если примитив добавлен дополнительным
  методом трейта с дефолтной реализацией; `### ⚠️ Breaking` + `### Migration`
  (минор в 0.x), если меняется сигнатура `apply_input`. Выбор варианта —
  первое решение этапа 4, см. stage_4.md.

Если правится крейт `core/`, за движком обязан пойти и `vimp-tanks`.

## Общая проверка

После каждого этапа, в `~/Sites/my/vimp-snakes`:

```bash
npm run core:test          # если менялся core/
npm run check:contract
npx eslint . && npm test
npm run core:build && npm run build
```

И из чекаута движка, с прилинкованным пакетом:

```bash
npm run sim -- --game ~/Sites/my/vimp-snakes \
  --scenario ~/Sites/my/vimp-snakes/scenarios/growth.json --determinism
```

Exit-код `sim` — вердикт: `0` означает, что все инварианты соблюдены.
Для правок самого движка — его собственные `npx eslint . && npm test` и
`npm run core:test`.
