# Этап 4: управление мышью и тачем

Пункт пользователя 6: игрок движется в зону клика, двойной клик — ускорение;
игра должна работать на смартфонах. Решение пользователя — **новый примитив
ввода в движке**, а не эмуляция клавиш на стороне игры.

Этап последний, потому что единственный меняет контракт плагина.

## 4.1. Что в движке есть сейчас (проверено по коду)

Канал ввода — строго дискретный, значения не переносит:

| Место | Что делает |
| --- | --- |
| `src/client/InputListener.js:23-27` | ловит `mousedown`/`mouseup`/`mousemove` и эмитит `mouseAction` **без единого аргумента** |
| `src/client/main.js:910-913` | `mouseAction` подписан ровно на `controls.resetCursorHideTimer` — это скрытие курсора, не игровой ввод |
| `src/client/components/model/Controls.js:56-63, 86-93` | клавиша → `publisher.emit('socket', 'down:<name>')` / `'up:<name>'` |
| `src/client/main.js:930-957` | разбирает `'action:name'`, зовёт `clientCore.apply_input(action, name, now)`, шлёт по проводу `PC_KEYS_DATA` строкой `'seq:action:name'` |
| `core/src/client/game.rs:94` | метод трейта `fn apply_input(&mut self, action: &str, key_name: &str, local_now: f64)` |

Touch-событий нет **вообще** — ни в `InputListener`, ни где-либо ещё.
То есть на смартфоне игра сейчас неуправляема в принципе.

## 4.2. Развилка, которую надо пройти первой

Аналоговый ввод (угол или точка) в существующую строку `action:name` не
влезает. Два способа:

**А. Дополнительный метод трейта (рекомендуется).** Добавить рядом с
`apply_input` новый метод — например `apply_aim(&mut self, angle: f32,
local_now: f64)` — **с дефолтной пустой реализацией**. Тогда:

- ни одна существующая игра не ломается, `vimp-tanks` можно не трогать;
- уровень релиза крейта и движка — `### Added` (минор), не Breaking;
- по проводу идёт отдельный подтип сообщения `PC_KEYS_DATA`, старый формат
  остаётся байт в байт прежним.

**Б. Расширить сигнатуру `apply_input` значением.** Чище выглядит, но
меняет метод трейта `vimp-engine-core`, то есть это `### ⚠️ Breaking` +
`### Migration` в **двух** changelog'ах, обязательный бамп крейта и
обязательная синхронная правка `vimp-tanks`.

Выбирать А, если не найдётся причины против. Решение зафиксировать в этом
файле до написания кода.

## 4.3. Работа в движке

1. **`InputListener.js`** — начать эмитить координаты. Слушать `pointerdown`
   / `pointermove` / `pointerup` вместо (или в дополнение к) мышиных: один
   набор Pointer Events закрывает и мышь, и палец, и стилус — это и есть
   ответ на «должно работать на смартфонах». Существующий `mouseAction` без
   аргументов **сохранить**: на нём висит скрытие курсора.
2. **Двойной клик/тап.** Не полагаться на `dblclick` — на тач-устройствах он
   не гарантирован. Распознавать самим: два `pointerdown` в пределах N мс и
   M пикселей. Пороги — константы конфига движка, а не магические числа.
3. **`components/model/Controls.js`** — новый канал, живущий по тем же
   правилам, что и клавиши: гасится при `_areKeysEnabled === false`, при
   открытом чате/голосовании, переключается вместе с `keySetList`. Иначе
   игрок будет рулить змейкой, набирая сообщение в чат.
4. **Координаты.** Указатель даёт координаты экрана, игре нужны мировые.
   Преобразование обязано жить в движке (у него камера и `CanvasManager`), а
   плагин должен получать уже готовую величину. **Решить, что именно
   передавать: мировую точку или сразу угол от головы игрока.** Угол проще
   для змейки, но точка универсальнее для других игр — а примитив
   добавляется в движок, то есть для всех. Скорее всего, точка.
5. **Провод и хост.** Провести значение через `PC_KEYS_DATA` до
   `src/host/PortMachine.js` и дальше в ядро хоста. Формат — расширение
   существующего, с сохранением обратной совместимости.
6. **Документация.** `docs/ai/04-client-plugin.md` (контракт плагина) плюс
   зеркальные страницы `docs/en/client.md` и `docs/ru/client.md` — правило
   движка требует править обе языковые версии **в том же изменении**.
7. **Тесты движка** — на распознавание двойного тапа, на гашение канала при
   открытом чате, на преобразование координат.

## 4.4. Работа в snakes

1. **Ядро.** `core/src/motion.rs` сейчас поворачивает змейку инкрементами от
   `left`/`right` с постоянной `turnSpeed`. Целевой угол — другой режим: «до
   какого угла доворачивать», по-прежнему **не быстрее** `turnSpeed`, иначе
   мышь даст мгновенный разворот и станет сильнее клавиатуры.
   Реализовать как одну функцию, к которой сводятся оба источника: клавиши
   задают цель «текущий угол ± шаг», указатель — «угол на точку». Тогда
   `GameSim` и `Predictor` продолжают делить один код, а это единственное,
   что удерживает предсказание в синхроне.
2. **Буст по двойному тапу.** Клавиатурный `boost` — удержание. Тап
   удержания не даёт, значит для указателя буст это импульс: включить и
   держать, пока палец на экране, либо на фиксированное время. Выбрать и
   записать; вариант «пока палец прижат» ближе к жанру.
3. **Предиктор.** Целевой угол должен приходить в предиктор тем же путём,
   что и клавиши, иначе локальная змейка поедет мимо авторитетной. Гонять
   `parity`-набор в `core/src/client/predictor.rs` после **каждой** правки
   движения — это единственный тест, ловящий изменение, применённое к одной
   половине из двух.
4. **Конфиг.** Указатель — не замена клавиатуре, а второй способ: `A`/`D`/`W`
   продолжают работать. На смартфоне доступен только указатель.
5. **Сценарий** `scenarios/pointer.json` — прогон на новом примитиве с
   жёсткими порогами дрейфа, по образцу `movement.json`.

## Проверки

- движок: `npx eslint . && npm test`, `npm run core:test`;
- snakes: `npm run core:test` (обязательно, менялось движение),
  `npm run check:contract`, `npx eslint . && npm test`;
- `npm run sim` по всем сценариям, включая новый, с `--determinism` —
  инвариант `predictionDrift` здесь главный;
- **проверить, что `vimp-tanks` продолжает собираться и проходить свои
  тесты** — при варианте А он не должен требовать правок, и это надо
  подтвердить, а не предположить;
- браузер: мышь на десктопе и реальный смартфон — поворот к точке,
  двойной тап даёт ускорение, чат и голосование не рулят змейкой.

## Релиз

Правится опубликованный код `vimp-engine` и, вероятно, крейт
`vimp-engine-core`. Обязательны записи в `packages/engine/CHANGELOG.md` и —
если тронут крейт — в `packages/engine/core/CHANGELOG.md`, под
`## [Unreleased]`:

- вариант А — `### Added` (минор) в обоих;
- вариант Б — `### ⚠️ Breaking` + `### Migration` в обоих, и `vimp-tanks`
  обязан пойти следом.

Отдельно решить, меняется ли `ENGINE_API_VERSION`: новый примитив, который
игра может не поддерживать, версию не поднимает; примитив, без которого
клиент не запускается, — поднимает. Версии пакетов не редактировать и не
публиковать.
