# Этап 1 — плавное появление змей (пункт 1) ✅ выполнен

## Требование

Новая змея не должна появляться внезапно: некоторое время она мигает и не
двигается, в это время она не убивает других и не может быть убита сама —
у соперника должно быть время увернуться.

Длительность: **`spawnGraceSeconds = 2.0`** (решение пользователя).

## Почему это касается и предиктора, и клиента

`core/src/motion.rs` — единственный источник движения, общий для хоста
(`Snake::step`) и клиентского предиктора (`core/src/client/predictor.rs`).
Локальный игрок тоже переживает грейс при своём спавне/респауне — если
предиктор не будет знать о заморозке, его змея на пару кадров разъедется с
сервером. Кадр `[x, y, cos, sin, crystals, length, alive, 0]`
(`core/src/snake.rs:293`, `prediction_state`) уже несёт восьмой, неиспользуемый
слот (жёстко `0.0`) — готовый канал для флага «сейчас в грейсе», без
расширения ширины кадра (`PLAYER_STATE_LEN = 8` — контрактная константа).

Для отрисовки мигания ВСЕХ змей нужен отдельный канал — проводная строка `s1`
(`src/config/snapshot.js:52`). Байт `boost` там `u8`, значения `0`/`1`;
контракт-тест жёстко проверяет ширину и порядок полей `s1`, свободного поля
нет. Занимаем **бит 1** байта `boost` (бит 0 — буст, бит 1 — грейс) вместо
добавления нового поля: ширина кадра не меняется.

## Изменения

- **`core/src/config.rs`** — `spawn_grace_seconds: f32` в `WorldConfig`
  (рядом с `start_crystals`, `edge_margin`); фикстуры в `config.rs::fixtures`
  обновить.
- **`src/data/models.js`** — `world.spawnGraceSeconds: 2.0`.
- **`core/src/snake.rs`** — поле `spawn_grace: f32` на `Snake`; выставляется в
  `new()` и `respawn()` из `world.spawn_grace_seconds`; геттер + декремент.
- **`core/src/game.rs`** (`on_fixed_step`):
  - пока `spawn_grace > 0`: не звать `snake.step(...)`, декрементировать грейс
    на `dt`, исключить из ОБОИХ циклов проверки столкновений (и как жертву, и
    как убийцу), не подбирать кристаллы;
  - `SnakeRow.boost` — писать бит 1, если `spawn_grace > 0`;
  - `prediction_state()` — слот 7 = `1.0` при `spawn_grace > 0`, иначе `0.0`.
- **`core/src/client/predictor.rs`** — читать слот 7 из серверного стейта;
  пока он `1.0`, локальный `step()` не двигает змею (паритет с хостом).
- **`src/client/parts/Snake.js`** — читать бит 1 байта `boost`; пока он
  установлен, пульсировать альфу тела/головы (~4 Гц) вместо обычной отрисовки;
  бит 0 читать как прежний признак буста.

## Тесты

- `core/src/snake.rs`, `core/src/game.rs` — свежеспавненная/зареспавненная
  змея не двигается и не участвует в столкновениях, пока `spawn_grace > 0`;
  после истечения — обычное поведение.
- `core/src/client/predictor.rs::mod parity` — новый кейс «во время грейса
  змея не двигается ни на хосте, ни в предикторе».
- `tests/client/parts.test.js` — рендер мигания по биту 1; буст по биту 0
  продолжает работать при одновременно взведённых битах.
- `tests/config/contract.test.js` — остаётся зелёным без изменений (ширина
  `s1` не меняется).
