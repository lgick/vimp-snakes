# Этап 3 — боты/игроки не должны появляться друг на друге (пункт 4)

## Диагноз (предыдущая версия этого файла была неверна)

Что НЕ является причиной, вопреки прошлому разбору:

- `ScriptedManager.createScripted` **уже** клэмпит число ботов по числу
  свободных точек спавна (`_hasRoom`, `src/host/ScriptedManager.js:91`);
- `respawns.players` содержит 64 точки при `roomDefaults.maxPlayers: 32`
  (`src/data/maps/arena.js:55`), так что `respawns[team][number]` в
  `RoundManager._startRound` за границу массива не выходит;
- минимальное попарное расстояние между всеми 64 точками — 178 единиц, что
  больше `RESPAWN_CLEARANCE = 140` (это и проверяет
  `tests/host/arenaScaler.test.js`).

Настоящих причин две.

**(а) Точки подсолнуха раздаются по возрастанию радиуса.**
`buildRespawns` (`src/data/maps/arena.js:83`) считает
`r = radius * 0.72 * sqrt((i + 0.5) / 64)`, а движок раздаёт точки строго по
индексу `0, 1, 2, …`. На базовой арене (радиус 1280) первые десять точек лежат
на радиусах **81, 141, 182, 216, 244, 270, 294, 315, 336, 355** — то есть
любые первые N игроков всегда оказываются в середине диска. Спираль равномерна
по площади только целиком; её ПРЕФИКС — нет. Плюс каждая точка смотрит строго
в центр (`theta + 180`), так что вся эта куча ещё и едет навстречу друг другу.

**(б) `/bot` сбрасывает размер арены.** `botCommand.handler` зовёт
`ctx.roundManager.initiateNewRound()`, а `RoundManager._startRound` делает
`this._game.createMap(this._scaledMapData)` — то есть возвращает ядру
БАЗОВУЮ карту движка (20 клеток, радиус 1280) мимо `ArenaScaler`. После
`/bot 20` двадцать змей расставляются по внутренним точкам базового диска, и
только следующее `population`-событие вернёт арене нужный размер — змеи к тому
моменту уже стоят кучей в центре большого диска.

## Изменения — три слоя (решение пользователя: берём все три)

### 1. `src/data/maps/arena.js` — порядок точек

Радиус берётся не из `sqrt((i+0.5)/N)`, а из радикал-инверсии по основанию 2
(последовательность ван дер Корпута): `r = radius * RESPAWN_SPAN *
sqrt(vdc2(i))`. Тогда ЛЮБОЙ префикс списка равномерен по площади всего диска,
а не только весь список целиком. Угол остаётся золотым (`i * GOLDEN_ANGLE`),
так что соседние по индексу точки расходятся и по углу.

Направление взгляда: не строго в центр, а в центр ± небольшой детерминированный
разброс (порядка ±25°), чтобы соседи по спавну не сходились в одну точку.
Разброс должен быть функцией `i`, не случайным — карта сериализуется в
`dist/maps/arena.json` и обязана совпадать у хоста и клиента.

Инвариант «минимум 140 единиц между любыми двумя точками» обязан сохраниться —
это уже проверяется тестом, добавить к нему проверку префиксов.

### 2. `core/src/game.rs` — защитный спавн

`spawn_actor` (`game.rs:444`) сегодня берёт `x, y, angle_deg` от движка как
есть, только `clamp_inside`. Ввести проверку клиренса по образцу уже
существующего `find_spawn` (`game.rs:189`): если в пределах
`RESPAWN_CLEARANCE` от переданной точки есть живая змея — искать свободную.

- `spawn_scripted_actor` (`game.rs:534`) получает `rng: &mut Rng` от движка —
  использовать `find_spawn` напрямую;
- `spawn_actor` в сигнатуре трейта `rng` не имеет — вынести из `find_spawn`
  общую часть (проверка клиренса + разворот на центр) и для не-scripted
  использовать детерминированный обход точек карты/спирали от `game_id`
  вместо случайных попыток. Сигнатуру трейта, которую диктует движок, не
  менять.

Этот слой закрывает и путь `RoundManager.changeTeam` (`RoundManager.js:376`),
где индекс точки считается как `getTeamSize(newTeam) - 1` и после серии
входов/выходов может указать на уже занятую точку.

### 3. `src/host/botCommand.js` — вернуть размер арены после рестарта

После `ctx.roundManager.initiateNewRound()` заново применить размер арены
через `ArenaScaler`. Ручка уже есть: `getArenaScaler()` из
`src/host/createModules.js:41` (тот же module-scope приём, что и у
`StatBridge`). Добавить в `ArenaScaler` публичный `reapply()`, который
пере-отправляет текущую `mapData` в `coreAdapter.createMap` + `_broadcast()`,
не трогая гистерезис `_size`/`_population`.

## Тесты

- `core/src/game.rs` — N змей, спавненных подряд с ОДНОЙ и той же переданной
  точкой, оказываются попарно дальше `RESPAWN_CLEARANCE`.
- `tests/host/arenaScaler.test.js` — к существующей проверке попарных
  расстояний добавить: первые 8 / 16 / 32 точки покрывают весь диапазон
  радиусов (например, максимальный радиус префикса из 8 точек не меньше
  половины `RESPAWN_SPAN * radius`); `reapply()` шлёт карту в ядро и клиентам.
- `tests/host/hostPlugin.test.js` — `/bot N` вызывает `initiateNewRound`, а
  затем `reapply`.

```bash
npm run check:contract
npx eslint . && npm test

```

Сценарий `bots` (`--determinism`): боты не должны взаимоубиваться в первые
секунды. Ручная: `/bot 20` на маленькой арене в `npm run dev` — змеи
расходятся по всему диску, а не сходятся в центр.

> Замечание: слой 1 и слой 3 борются с симптомом, слой 2 — с последствием.
> Первопричина (`_startRound` возвращает ядру карту движка, а не ту, что в
> силе) живёт в движке и здесь НЕ чинится: `ArenaScaler` работает мимо
> движкового пути смены карты сознательно, чтобы не терять счёт (см. шапку
> `src/host/ArenaScaler.js`).
