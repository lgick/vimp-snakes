# План: snakes v3 — три рейтинга, скины за топ-10 и предел записи в БД

Индекс. План писался так, чтобы его мог исполнить кто угодно без
дополнительного контекста: в каждом файле стадии есть пути, текущее
состояние кода, целевой вид, контракты данных, тесты и команды проверки.

## Три репозитория (пути абсолютные, они понадобятся)

| Что | Путь | Как проверяется |
| --- | --- | --- |
| Игра snakes | `/Users/dmitry/Sites/my/vimp-snakes` | `npm test`, `npm run core:test`, `npm run check:contract`, `npm run sim` |
| Движок + мастер | `/Users/dmitry/Sites/my/vimp/packages/engine` | тесты лежат НЕ в пакете: `cd /Users/dmitry/Sites/my/vimp && npm test` |
| auth-сервис | `/Users/dmitry/Sites/my/vimp/packages/auth` | там же: `cd /Users/dmitry/Sites/my/vimp && npm test` (файлы `tests/auth/*`) |

`node_modules/vimp-engine` в snakes — симлинк на пакет движка, поэтому
правка движка видна игре сразу, без переустановки.

Монорепо `vimp` использует vitest с глобалами (`describe/it/expect/vi` без
импорта в части файлов; в snakes они импортируются явно — смотри соседние
тесты и повторяй стиль файла, в который пишешь).

## Решения пользователя (зафиксированы, не переспрашивать)

1. **«Игра» = одна жизнь.** Score обнуляется на респауне, в панели 0.
2. **Буст сжигает кристаллы и вычитает их из score.**
3. **Daily** — лучший результат ОДНОЙ игры за сутки UTC, в реальном
   времени, сброс в 00:00 UTC.
4. **Monthly** — СУММА очков всех игр за календарный месяц UTC, в реальном
   времени.
5. **All-time** — сумма всех очков за всё время, пересчёт раз в сутки; и
   список, и своя строка показывают снимок на 00:00 UTC.
6. **Награды** (механизм общий для любой игры, сами награды — только у
   snakes): top-10 daily → ромб на теле змеи, top-10 monthly → корона на
   голове. Живут по ТЕКУЩЕМУ месту, привязаны к нику (он глобально
   уникален), работают на любом сервере, видны ТОЛЬКО в матче.
7. В stat по `Tab` — только дневной топ-10; если игрок не в топе, его
   строка заменяет десятую. Без `.stat-head`, без колонки `rank`.
8. `/rank` в чате отвечает местом в дневном рейтинге.
9. **Игр сотни, серверов сотни.** Не изменилось — не отправляем; данные при
   этом всегда актуальны. Пределы записи держит движок, а не игра.

Порядок обязателен: хост не может вычесть буст без события ядра (1); движку
нечего отправлять, пока auth не принимает результат игры (2); `accolades` и
таблица опираются на готовые срезы (3→4); игра — на всё перечисленное (5).

Тесты не откладываются в конец: каждая стадия заканчивается зелёными
тестами своей стадии (правило `CLAUDE.md` обоих репозиториев). Этап 6 — это
документация и сквозная живая проверка, а не «дописать тесты потом».

## Что ломается совместимостью (прочитать до начала)

- Этап 4 добавляет порт в `wsports` и пятый сервис в пул зависимостей →
  `ENGINE_API_VERSION` в
  `/Users/dmitry/Sites/my/vimp/packages/engine/src/config/opcodes.js`
  поднимается `3 → 4`. `GameCatalog` (мастер) молча пропускает игру,
  собранную под другую версию, поэтому после правки движка snakes
  ОБЯЗАТЕЛЬНО пересобирается `npm run build`, иначе игра просто исчезнет из
  лобби без единой ошибки.
- Этап 2 меняет смысл `rank_events.delta`: это больше не «дельта ранга», а
  сумма очков игр. Существующие строки трактуются как есть, миграция
  проставляет им `best = GREATEST(delta, 0)`.
